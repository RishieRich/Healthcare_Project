# Code Review — 2025-12-21

## Scope and approach
- Performed a quick, file-level review of the Python source (`patient_dashboard.py`), the existing tests, and the top-level documentation to identify correctness risks, maintainability issues, and coverage gaps.

## Strengths
- `add_total_expense_column` defends against malformed numeric inputs by coercing values to numeric and filling missing entries before aggregation, which reduces runtime failures on dirty data sets.【F:patient_dashboard.py†L12-L49】
- The class offers focused helper methods for patient ordering and age enrichment that make the intended data transformations discoverable and reusable.【F:patient_dashboard.py†L51-L79】

## Findings and recommendations
1) **In-place mutation creates hidden coupling**
   - `add_total_expense_column` reuses the provided DataFrame reference and adds the `added_amt` column in place; `fetch_patient_by_age` also writes an `age` column directly onto the input before sorting.【F:patient_dashboard.py†L27-L49】【F:patient_dashboard.py†L61-L77】
   - Downstream callers that reuse the original frames may see surprising columns or overwritten values. Prefer working on `df.copy()` and returning the new frame to keep the helpers side-effect free.

2) **CSV ingestion lacks configurability and validation**
   - `read_csv` hard-codes comma delimiters and exposes no error handling or dtype/date parsing controls, which can lead to silent type drift or memory blow-ups on larger files.【F:patient_dashboard.py†L8-L10】
   - Consider allowing delimiter and dtype parameters, enabling `low_memory=False` (or chunked reads), and surfacing a clear error message when a file cannot be read.

3) **Assumptions about prerequisite columns are unchecked**
   - `fetch_patient_phone` assumes `added_amt` already exists; if callers forget to run the expense aggregation first, it raises a `KeyError` from `nlargest`/`nsmallest` with little context.【F:patient_dashboard.py†L51-L59】
   - Guard with an explicit presence check (or compute it when missing) and provide a helpful error explaining the dependency.

4) **Age enrichment overwrites data and does not validate joins**
   - Mapping patient ages overwrites any preexisting `age` values and leaves nulls when a discharge row lacks a matching patient detail, yet the result is sorted as if all ages are present.【F:patient_dashboard.py†L61-L77】
   - Build a defensive join (e.g., merge on `registrationno` with an indicator), preserve existing `age` when already set, and decide how to treat missing matches (drop or flag) before ordering.

5) **Test coverage is narrow**
   - Current tests only exercise `add_total_expense_column` for happy-path aggregation and missing-column validation; other methods (`read_csv`, `fetch_patient_phone`, `fetch_patient_by_age`, `to_csv`) are untested, leaving behavior and failure modes unguarded.【F:tests/test_patient_dashboard.py†L10-L39】
   - Add tests for ordering logic, age merge edge cases (missing registrations, duplicate keys), CSV IO errors, and ensuring helper methods do not mutate inputs unexpectedly.

## Quick-win suggestions
- Make helper methods pure by copying inputs before augmentation.
- Add lightweight validations for required columns and clearer error messages.
- Expand unit tests to cover ordering, join behavior, IO errors, and immutability.
